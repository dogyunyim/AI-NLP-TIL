# 서브워드 실습 검토

검토일: 2026-09-06 · 대상: [2026.06.25 실습 노트북](<../Subword_problem_(2026.06.25 실습과제).ipynb>)

원본 코드와 저장된 출력을 보존한 상태에서, 구현 범위와 결과 해석의 한계를 정리했습니다. 아래 개선안은 **아직 적용하거나 재실행하지 않은 후속 과제**입니다.

## 코드에서 확인한 구현

| 단계 | 확인 내용 |
|---|---|
| 데이터 처리 | NSMC TSV 로드 → `document` 선택 → `dropna()` → 줄 단위 텍스트 저장 |
| 토크나이저 학습 | SentencePiece `model_type='unigram'`, Hugging Face `BPE()`와 `Whitespace()` |
| 사전·분절 확인 | 사전 항목 출력, 코퍼스 전체 분절 후 `Counter.most_common(30)` |
| 시간 측정 | `time.time()`을 이용한 단일 문장 및 코퍼스 인코딩 |
| 추가 입력 | 한국어 복합 표현을 SentencePiece로 분절 |

## 결과를 읽을 때 주의할 점

1. **라이브러리만 바꾼 비교가 아닙니다.** Unigram과 BPE는 알고리즘이 다르고 전처리도 다릅니다. 관찰된 차이를 라이브러리 자체의 속도·품질 차이로만 해석할 수 없습니다.
2. **사전 순서와 출현 빈도는 다릅니다.** `spm.vocab`의 앞 30개나 토큰 ID순 첫 30개는 코퍼스의 빈도 TOP 30과 같지 않습니다. 빈도 분석은 뒤쪽 `Counter` 셀과 구분해야 합니다.
3. **단일 측정값은 일반적인 성능 지표가 아닙니다.** 워밍업·반복·측정 순서 교차·환경 기록이 없습니다. `time.perf_counter()`로 여러 번 측정하고 중앙값과 변동 범위를 함께 확인할 필요가 있습니다.
4. **학습 시간 측정은 구현되지 않았습니다.** 과제 목차에는 단어사전 구축 속도가 있지만, 두 학습 호출을 감싼 시간 측정 코드는 확인되지 않습니다. 현재 기록은 인코딩 시간 비교입니다.
5. **미등록 토큰 처리를 별도 확인해야 합니다.** `BpeTrainer`에 `[UNK]`를 추가했지만 `BPE()`의 `unk_token` 인자는 지정하지 않았습니다. 어휘에 없는 문자를 넣어 동작을 검증하고 `BPE(unk_token='[UNK]')` 등 명시적인 설정을 검토해야 합니다.
6. **추가 입력은 양쪽 비교가 아닙니다.** 복합 표현 테스트는 SentencePiece에만 수행됩니다. 이를 근거로 BPE와의 OOV 처리 우열이나 OOV가 없음을 주장할 수 없습니다.
7. **재현 조건이 충분하지 않습니다.** 라이브러리 버전 고정, 다운로드 응답 상태 확인, 데이터 버전·해시, 실행 환경과 검증용 문장 집합을 보완해야 합니다.

## 다음 실험 제안

- 동일한 데이터·정규화·사전 크기로 알고리즘과 전처리 변수를 나누어 비교
- 학습 시간과 인코딩 시간을 구분해 반복 측정
- 두 토크나이저에 같은 입력을 넣고 미등록 문자·한국어 복합어의 분절과 복원 결과 확인
- 측정 조건과 한계를 결과표 옆에 기록

이 기록은 잘된 결과만 강조하기보다 **실험 조건과 판단 범위를 함께 설명하기 위한 검토 문서**입니다.
